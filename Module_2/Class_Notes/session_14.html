Core lesson · Module 2 Revision and Doubt Session
01

How to think about it

A secure operations workflow starts with identity and scope, uses least privilege, records actions, validates inputs, and preserves evidence. Linux permissions protect local files; Bash automates repeatable checks; logs provide event records; parsing turns records into fields; Git tracks reviewed code. Active Directory organizes identities and policy in Windows domains, but directory membership does not replace endpoint hardening, strong authentication, monitoring, and careful administration.

Key facts to remember
  • Hardening reduces attack surface through updates, secure configuration, least privilege, and removal of unnecessary services.
  • CIS Benchmarks are configuration guidance; choose the correct OS/version and assess operational impact before applying settings.
  • Logs, metrics, and traces have distinct roles; correlate them with timestamps and stable identifiers.
  • A portfolio repository is a record of work, not a place for credentials or unredacted logs.
Python and Active Directory recap

Python sockets: a socket is a communication endpoint. For a small defensive automation task, name one approved lab host, set a short timeout, handle connection errors, limit the number of attempts, and log the result. A socket script is not permission to scan a network and should not be treated as a replacement for a purpose-built, scoped tool.

AD DS: a directory stores network objects such as users and computers. A forest contains domains; organizational units group objects for administration and Group Policy. Domain controllers provide directory and authentication services. Protect privileged groups, review delegated rights, apply tested baselines, and monitor changes.

Worked example
02

Follow the evidence

A Linux server audit finds a world-readable script, an old package, and repeated failed SSH logins. The reviewer validates the permissions and package version, checks whether failures share a source or relate to normal automation, records a proposed fix, applies it only in the lab, then verifies and commits the sanitized check script.

Reasoning sequence
  1. Explain the difference between owner/group/other and an AD group policy.
  2. Use a Bash script to inspect a synthetic log and emit a summary.
  3. Map one log event to a possible metric and trace context.
  4. Describe the review, evidence, and privacy steps before pushing the script to Git.

Retrieval practice · answer before revealing
04

Check what you remember

Close the lesson notes, answer each question from memory, then open the explanation and correct your own answer.

Question: What is the difference between authentication and authorization?

Reveal answer and reasoning

Authentication verifies identity; authorization decides what that identity may do.

Question: What does a hardened baseline provide?

Reveal answer and reasoning

A starting configuration that reduces common exposure; it does not guarantee a system is secure.

Question: How should an analyst handle an ambiguous log pattern?

Reveal answer and reasoning

Preserve context, form alternative hypotheses, seek corroborating sources, and state confidence rather than asserting an incident.

If your answer differs, explain why. The reveal gives the reasoning, not merely a keyword.

Common mistakes
05

Where learners overclaim

Use these corrections to review your notes and lab evidence.

Avoid these shortcuts
  • Confusing tool output with verified truth. Validate results against a second source.
  • Making production changes without owner approval, rollback planning, or validation.
  • Pushing real credentials or classmate information into a repository.
