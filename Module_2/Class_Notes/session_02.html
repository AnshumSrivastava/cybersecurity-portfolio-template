File Permissions

Revision route: understand the model · work through evidence · practice safely · check recall · review sources.

Core lesson · File Permissions
01

How to think about it

Each filesystem object has an owner user, an owner group, and permission bits for user/group/other. Read means view file data (or list directory names); write means modify file data (or directory entries); execute means run a file or traverse a directory. The kernel evaluates the applicable identity class; root and ACLs introduce additional behavior. `chmod` changes mode bits, while `chown` changes ownership.

Key facts to remember
  • `ls -l` displays a mode such as `-rwxr-x---`: file type, user, group, other.
  • Numeric modes add r=4, w=2, x=1 per class; `750` means owner rwx, group r-x, other none.
  • Directory execute permission allows traversal; read permission allows listing names.
  • Use least privilege. Avoid `777`; it makes every local user able to write and execute.

Worked example
02

Follow the evidence

A report owned by `analyst:team` has mode 640. The owner can read/write, the group can read, and others have no access. If the file is inside a directory lacking execute permission for the group, group members still cannot reach it.

Reasoning sequence
  1. Inspect owner, group, mode, and parent-directory permissions with `ls -l` and `namei -l` on the lab file.
  2. Predict access for owner, group member, and unrelated user.
  3. Change only the disposable file with an instructor-approved symbolic or numeric `chmod`.
  4. Re-check the mode and test access with the supplied test account.

Retrieval practice · answer before revealing
04

Check what you remember

Close the lesson notes, answer each question from memory, then open the explanation and correct your own answer.

Question: What does execute permission on a directory allow?

Reveal answer and reasoning

Traversal/search through the directory when its path is known; it is distinct from listing names.

Question: What does mode 640 mean?

Reveal answer and reasoning

Owner read/write, group read, others no permissions.

Question: Why is `chmod 777` rarely appropriate?

Reveal answer and reasoning

It grants read/write/execute to everyone and often exceeds the task’s access need.

If your answer differs, explain why. The reveal gives the reasoning, not merely a keyword.

Common mistakes
05

Where learners overclaim

Use these corrections to review your notes and lab evidence.

Avoid these shortcuts
  • Reading a directory mode as if it were a file mode. Directory `x` controls traversal.
  • Changing only the file while forgetting restrictive parent directories. Check the full path.
  • Assuming mode bits are the only access control. ACLs, mount options, capabilities, and privileged accounts can also affect access.
