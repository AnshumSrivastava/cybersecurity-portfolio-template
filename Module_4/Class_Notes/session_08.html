Inspect a file without executing it and extract indicators with provenance and confidence.

Core lesson · Static Analysis Fundamentals
01

How to think about it

Static analysis examines a file’s bytes and structure without running it. Basic checks include hash, file signature, size, strings, metadata, imports, sections, and embedded content. Static indicators can guide hypotheses but are not verdicts: benign tools can contain suspicious strings, and malware can obfuscate or encrypt content. Analyze only provided copies in a controlled lab; treat extracted URLs and commands as inert text, never visit or run them.

Key facts to remember
  • File extensions are labels; magic bytes and format parsers provide stronger type clues.
  • Strings and imports are leads, not proof of behavior.
  • Hash lookups depend on database coverage and sample identity.
  • Keep indicators context-rich: source, time, hash, extraction method, and confidence.
Use this mental model

For every security claim, name the asset and scope, identify what was directly observed, explain the control or mechanism, and state what remains uncertain. Prefer a small, reproducible check over assumptions based on a tool label.

This lesson is designed to stand alone. Read the explanation, follow the example, then complete the practice and retrieval questions before using the linked references.

Worked example
02

Follow the evidence

A harmless training binary contains a URL-like string. The analyst records the string and sample hash but does not connect to it. They inspect imports for networking and file operations, then explain that the static evidence suggests capabilities, not that those actions occurred.

Reasoning sequence
  1. Verify sample identity with a hash.
  2. Read file type, metadata, and strings using approved offline tools.
  3. Correlate a candidate IOC against the instructor’s offline dataset.
  4. State what static evidence can and cannot establish.
Conclusion discipline

Write the observation first, the interpretation second, and the confidence/limitation last. A useful answer says what would change your conclusion and which source could verify it.

Try it: Can a classmate reproduce your reasoning using only the evidence you recorded?

Guided practice
03

Practice in scope

Inspect an inert sample with `file`, `sha256sum`, and a strings viewer in the lab VM. Do not execute the sample or open extracted links.

Procedure
  1. Verify sample identity with a hash.
  2. Read file type, metadata, and strings using approved offline tools.
  3. Correlate a candidate IOC against the instructor’s offline dataset.
  4. State what static evidence can and cannot establish.
Submit this evidence

Hash and metadata table, selected strings/imports with byte/source context, and a behavior hypothesis with confidence.

Safety: use only the assigned dataset, VM, account, and target. Stop at the written scope boundary and preserve only sanitized evidence.

Retrieval practice · answer before revealing
04

Check what you remember

Close the lesson notes, answer each question from memory, then open the explanation and correct your own answer.

Question: What does an imported networking library prove?

Reveal answer and reasoning

Only that the program references that capability; it does not prove the function was used.

Question: Why verify a file signature?

Reveal answer and reasoning

The extension may be misleading; internal structure helps identify the actual format.

Question: Should an extracted URL be opened to see whether it is malicious?

Reveal answer and reasoning

No. Treat it as inert evidence and use approved offline reputation data or a controlled analysis environment.

If your answer differs, explain why. The reveal gives the reasoning, not merely a keyword.

Common mistakes
05

Where learners overclaim

Use these corrections to review your notes and lab evidence.

Avoid these shortcuts
  • Treating strings as a complete execution trace.
  • Executing the artifact because static analysis is inconclusive.
  • Copying IOCs without recording the sample hash and source.
Self-check before moving on
  • Can I explain the core mechanism without naming a tool first?
  • Can I reproduce the example and identify its evidence source?
  • Can I state one limitation, alternative explanation, and safe next step?
